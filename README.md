# Планнер Вити — безопасная авторизация

В исходном HTML пароль был захардкожен в JavaScript, поэтому любой посетитель мог открыть исходный код и увидеть его. Исправленная версия убирает логин/пароль из браузерного кода.

## Что изменено

- HTML больше не содержит `ADMIN_EMAIL` или `ADMIN_PASSWORD`.
- Проверка email и пароля выполняется на сервере.
- В Render хранится `ADMIN_EMAIL`, bcrypt-хеш пароля и секрет сессии.
- Пароль не записывается в `console.log`.
- После входа браузер получает только `HttpOnly` cookie; JavaScript не может прочитать её через `document.cookie` или `localStorage`.
- Сессия имеет срок действия 12 часов.
- Добавлено ограничение частоты попыток входа.

## Важно

Пароль, который был в старом HTML, уже нельзя считать секретом. Перед публикацией создай новый пароль и используй его только для Render.

## Render

Используй **Web Service**, а не чистый Static Site, потому что авторизация теперь требует серверных `/api/auth/*` маршрутов.

Build Command:

```bash
npm install
```

Start Command:

```bash
npm start
```

Добавь в Render → Environment Variables:

```text
ADMIN_EMAIL=твой-email
ADMIN_PASSWORD_HASH=...
SESSION_SECRET=...
```

Не добавляй реальные значения в Git.

## Создание bcrypt-хеша

После `npm install` локально выполни:

```bash
node scripts/hash-password.js
```

Пароль вводится без отображения символов. Полученный `ADMIN_PASSWORD_HASH=...` вставь в Render.

Для `SESSION_SECRET` используй длинное случайное значение. Например, его можно сгенерировать локально:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## Структура

- `public/index.html` — исправленный frontend.
- `server.js` — сервер и API авторизации.
- `package.json` — зависимости.
- `scripts/hash-password.js` — безопасное создание bcrypt-хеша.

### Важное ограничение текущего приложения

Авторизация теперь серверная, но сами заметки/задачи в исходном приложении всё ещё сохраняются в `localStorage`. Это означает, что это **не серверная защита данных**: пользователь может менять локальные данные в своём браузере.

Если нужно действительно защитить админские данные от обхода через DevTools, следующим шагом нужно вынести заметки, задачи, импорт/экспорт и другие операции администратора на сервер/API и хранить их в базе данных.

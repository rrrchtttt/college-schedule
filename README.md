# Планнер Вити — Secure v3

Это версия сайта «Планнер Вити» с серверной авторизацией и правами доступа.

## Что сделано

- Сохранён исходный интерфейс планнера.
- Пароль администратора не находится в `index.html`, GitHub или браузерном JavaScript.
- Администратор задаётся через Render Environment Variables.
- Пароль администратора хранится только как bcrypt-хеш (`ADMIN_PASSWORD_HASH`).
- Сессия хранится в HttpOnly Secure cookie.
- Гость может просматривать расписание.
- Обычный пользователь может войти, но не получает права администратора.
- Только администратор может менять общие данные, импортировать/экспортировать резервные копии, создавать и удалять пользователей, редактировать расписание и отмечать посещаемость.
- Добавлено меню-гамбургер в правом верхнем углу.
- Встроено расписание группы БГО-101 на 1 семестр 2026–2027 из предоставленного PDF.

## Файлы

- `index.html` — интерфейс сайта.
- `server.js` — сервер, авторизация и защищённые API.
- `schedule.json` — исходное расписание.
- `hash-password.js` — локальный генератор bcrypt-хеша.
- `package.json` — зависимости и запуск.
- `README.md` — эта инструкция.

## Render Environment Variables

Создай три переменные:

- `ADMIN_EMAIL` — email администратора.
- `ADMIN_PASSWORD_HASH` — bcrypt-хеш текущего пароля, НЕ сам пароль.
- `SESSION_SECRET` — длинная случайная секретная строка.

### Как получить ADMIN_PASSWORD_HASH

На компьютере с Node.js:

```bash
npm install
node hash-password.js "ТВОЙ_ПАРОЛЬ"
```

Скопируй получившуюся строку в значение `ADMIN_PASSWORD_HASH` в Render.

Сам пароль в GitHub не записывай.

## Важно про Render-хранилище

Файлы `server-data.json` и `users.json` специально добавлены в `.gitignore`, поэтому они не попадают в GitHub. На Render файловое хранилище обычного сервиса может быть непостоянным после некоторых операций с сервисом. Для действительно постоянного хранения пользовательских данных и изменений расписания лучше подключить постоянный диск или базу данных. До этого резервные копии нужно периодически скачивать из админ-панели.

## Безопасность

Ни `ADMIN_PASSWORD_HASH`, ни `ADMIN_EMAIL`, ни `SESSION_SECRET` не должны быть вставлены в `index.html`.

Если настоящий пароль когда-либо публиковался в переписке или другом открытом месте, после завершения настройки его рекомендуется заменить.
